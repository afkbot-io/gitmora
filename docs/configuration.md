# Configuration reference

This is the complete supported operator configuration for the API, worker, CLI and shipped Compose profiles. Examples contain no real credentials. `python3 scripts/check-configuration.py` checks this reference against production source and Compose variables.

## Files and precedence

| File | Purpose | Created by / example |
| --- | --- | --- |
| `<app state>/installation.json` | Pinned image, port, ordered overlays, absolute paths and Compose project UUID | `gitmorad deployment init`; do not copy another installation's IDs into it |
| `<app state>/compose.env` | Hostnames, private subnet and provider relay policies used by Compose interpolation | Copy [`.env.example`](../.env.example), edit, `chmod 600` |
| `<app state>/runtime.env` | Non-secret API/worker runtime settings | Copy [runtime example](../deploy/gitmora.runtime.env.example), `chmod 600` |
| `<app state>/secrets/*` | Database URL/passwords, encryption keyring, OIDC client secret | Generated by `deployment init`; copy only the selected IdP client-secret file when enabling login |
| `<identity state>/identity.json` | Provider origin, callback origin, realm/client, exact subjects, images and ports | `identity-server init` |
| `<identity state>/operator.json` | Private provider recovery/admin credentials | Generated; never a public env example |
| `<identity state>/secrets/*` | Private Keycloak and database configuration | Generated; no manual passwords required |

The operator CLI automatically uses the application's private `compose.env` on every `deployment up/down/status/admin` operation when the file exists. Old installations without it keep their previous behavior. The file must be a regular, non-symlinked private file, at most 64 KiB. Identity settings are persisted separately by `identity-server init` flags; do not place its generated `GITMORA_IDENTITY_*` values into application `runtime.env`.

`compose.env` is for interpolation; `runtime.env` is passed to application containers. One does not substitute the other. Explicit shell exports override env-file interpolation; Compose service `environment` overrides the shared `env_file`. The identity activation overlay derives API public URL and issuer from `GITMORA_PUBLIC_HOST`. See [Compose precedence](https://docs.docker.com/compose/how-tos/environment-variables/envvars-precedence/). Keep unrelated root `.env` files out of the source checkout. Never run `docker compose config` on a profile with literal secrets and publish its output.

## Server runtime variables

| Variable | Default / format | Role and use |
| --- | --- | --- |
| `WORKGRAPH_DATABASE_URL` / `WORKGRAPH_DATABASE_URL_FILE` | Required PostgreSQL DSN; generated Docker file `/run/secrets/database_url` | API, worker and database-owner commands. Native/remote databases require appropriate TLS; Docker's generated DSN uses the isolated private network. pgx supports `pool_max_conns=8` in the DSN; tune against the database, not client count. |
| `WORKGRAPH_PUBLIC_URL` | Exact HTTPS origin, e.g. `https://gitmora.example.com`; no application subpath | API login/callback, browser origin and MCP public Host validation behind a reverse proxy. Shared-domain overlay supplies it from `GITMORA_PUBLIC_HOST`. |
| `WORKGRAPH_REGISTRATION_ENABLED` | `false`; only literal `true` opens signup | API; apply the same explicit value with `identity-server configure/up`. A provider restart with the variable unset preserves its existing durable policy. Does not disable authentication. |
| `WORKGRAPH_ENCRYPTION_KEYS` / `WORKGRAPH_ENCRYPTION_KEYS_FILE` | JSON object of key ID → standard base64 **32-byte** key | API/worker when integrations are enabled. Docker file `/run/secrets/encryption_keys`; generated automatically. Preserve old keys during deliberate rotation so stored envelopes remain readable. |
| `WORKGRAPH_ENCRYPTION_ACTIVE_KEY` | Generated ID `primary`; must exist in keyring | API/worker integration credential encryption. |
| `WORKGRAPH_OIDC_ISSUER` | Exact provider URL, e.g. `https://gitmora.example.com/auth/realms/gitmora` | API only. All issuer/client/secret settings must be configured together. |
| `WORKGRAPH_OIDC_CLIENT_ID` | Managed client `gitmora` | API only; must match the provider profile. |
| `WORKGRAPH_OIDC_CLIENT_SECRET` / `WORKGRAPH_OIDC_CLIENT_SECRET_FILE` | Managed confidential client secret; Docker file `/run/secrets/oidc_client_secret` | API only. Generated by `identity-server init`; copy its dedicated file to the app slot. |
| `WORKGRAPH_OIDC_AUTH_STYLE` | `basic`; also `post` | API only; provider token-endpoint client authentication. |
| `WORKGRAPH_OIDC_SESSION_SECONDS` | `28800`; allowed `900..28800` | API only; browser session maximum. |
| `WORKGRAPH_MCP_ALLOWED_ORIGINS` | Empty; comma-separated browser origins without paths | API HTTP MCP Origin policy. Native stdio MCP needs no browser Origin entry. It controls explicit MCP browser/CORS permission, not authentication or project access. |
| `WORKGRAPH_GITLAB_ALLOWLIST` | Empty; comma-separated canonical HTTPS installation bases | API/worker. A base may include a port and installation prefix, e.g. `https://code.example.com:8443/gitlab`. Empty disables GitLab. |
| `WORKGRAPH_GITLAB_PROXY_URL` | Empty; explicit private `http://host:port` CONNECT proxy | API/worker. Docker relay profile supplies `http://gitlab-egress:8080`; HTTPS remains end-to-end. |
| `WORKGRAPH_GITHUB_ENABLED` | Empty/`false`; enable with `true` | API/worker. Additional GitHub settings require enabled=true. |
| `WORKGRAPH_GITHUB_API_URL` | Fixed `https://api.github.com`; override only for explicit loopback test fixtures | API/worker. This is **not** the Enterprise setting. |
| `WORKGRAPH_GITHUB_PROXY_URL` | Empty; Docker public relay `http://github-egress:8080` | API/worker, GitHub.com only. |
| `WORKGRAPH_GITHUB_ALLOWLIST` | Empty; comma-separated Enterprise HTTPS **web bases** | API/worker. Enterprise API is `<web base>/api/v3`; ports/prefixes are retained. |
| `WORKGRAPH_GITHUB_PRIVATE` | Empty/`false`; explicit `true` | Direct/native Enterprise private routing only. For Docker use the selected relay's visibility. |
| `WORKGRAPH_GITHUB_ENTERPRISE_PROXY_URL` | Empty; explicit private CONNECT proxy | API/worker. Independent of GitHub.com proxy. |
| `WORKGRAPH_TASKTOPIA_ALLOWLIST` | Empty; comma-separated exact HTTPS URLs ending in `/mcp` | API/worker. Empty disables Tasktopia. Optional prefix/port is supported. |
| `WORKGRAPH_TASKTOPIA_PROXY_URL` | Empty; explicit private CONNECT proxy | API/worker remote Tasktopia route. Requires allowlist and HTTPS; Docker profile supplies `http://tasktopia-egress:8080`. |
| `SSL_CERT_FILE` | System trust by default; optional readable PEM bundle | Linux process TLS trust. A custom container bundle must retain required system roots and include the corporate CA; never put a private key into it. API/worker need the same trust for their source calls. |

For each sensitive value, select the direct variable **or** its `_FILE` form. Defining both is an error even when the direct value is empty. File paths must be absolute regular nonempty files, at most 64 KiB. Generated secret files are container-readable behind a `0700` host directory; do not change their permissions to a mode that prevents the container UID from reading them. Actual GitHub/GitLab/Tasktopia service tokens are saved through the authenticated connection form/API, encrypted in the database; they are not deployment env variables.

For native API operation the equivalent minimal settings are:

```sh
export WORKGRAPH_DATABASE_URL_FILE=/absolute/private/database-url
export WORKGRAPH_PUBLIC_URL=https://gitmora.example.com
export WORKGRAPH_REGISTRATION_ENABLED=false
export WORKGRAPH_OIDC_ISSUER=https://gitmora.example.com/auth/realms/gitmora
export WORKGRAPH_OIDC_CLIENT_ID=gitmora
export WORKGRAPH_OIDC_CLIENT_SECRET_FILE=/absolute/private/oidc-client-secret
export WORKGRAPH_ENCRYPTION_KEYS_FILE=/absolute/private/keyring.json
export WORKGRAPH_ENCRYPTION_ACTIVE_KEY=primary
# Enable only the sources you use, with their explicit routes.
gitmorad migrate
gitmorad serve --listen 127.0.0.1:8080
# Run worker separately with database/encryption/source settings; it needs no OIDC secret.
```

Without an OIDC configuration, capture/API/MCP bearer operations can be used for isolated development, but ordinary web/CLI account login is unavailable. Production instructions configure the provider.

## Compose/operator variables

| Variable | Source / example |
| --- | --- |
| `WORKGRAPH_STATE_DIR`, `WORKGRAPH_IMAGE`, `WORKGRAPH_HTTP_PORT` | Supplied by `deployment` from `--directory`, `--image`, `--port`; do not try to override pinned metadata in `compose.env`. For a deliberate raw Compose command, supply these yourself. |
| `GITMORA_PUBLIC_HOST` | `gitmora.example.com`, hostname only. Shared-domain API public origin, issuer and private host mapping derive from it. |
| `GITMORA_REALM`, `GITMORA_CLIENT_ID` | `gitmora`; match `identity-server init --realm/--client-id` and nginx realm route. |
| `GITMORA_POSTGRES_IMAGE` | `gitmora-postgres:18.6-security1`; prebuild the pinned image. Identity uses its own default unless explicitly exported during identity operations. |
| `GITMORA_PRIVATE_SUBNET`, `GITMORA_PRIVATE_GATEWAY` | `172.30.88.0/24`, `172.30.88.1`; choose an unused range before the first start. Used by same-host identity/Tasktopia profiles. |
| `GITMORA_TASKTOPIA_HOST` | Optional same-host HTTPS hostname; also set matching runtime endpoint allowlist. |
| `GITMORA_GITLAB_URL`, `GITMORA_GITLAB_AUTHORITY`, `GITMORA_GITLAB_VISIBILITY` | Custom GitLab web base, exact `host:port`, and `private`/`public` relay policy. |
| `GITMORA_GITLAB_CA_BUNDLE` | Absolute public CA bundle for the optional CA overlay. Although named for GitLab, it sets the process-wide `SSL_CERT_FILE` for all provider clients. |
| `GITMORA_GITHUB_ENTERPRISE_URL`, `GITMORA_GITHUB_ENTERPRISE_AUTHORITY`, `GITMORA_GITHUB_ENTERPRISE_VISIBILITY` | Enterprise web base, exact TLS authority, relay `private`/`public`. |
| `GITMORA_TASKTOPIA_URL`, `GITMORA_TASKTOPIA_AUTHORITY`, `GITMORA_TASKTOPIA_VISIBILITY` | Remote HTTPS MCP endpoint, exact TLS authority, relay `private`/`public`. |
| `GITMORA_IDENTITY_STATE`, `GITMORA_IDENTITY_HTTP_PORT`, `GITMORA_IDENTITY_IMAGE`, `GITMORA_IDENTITY_GATEWAY_IMAGE` | Generated from the selected identity profile/directory; ordinary CLI operations supply them. |
| `GITMORA_IDENTITY_REALM`, `GITMORA_IDENTITY_PUBLIC_URL`, `GITMORA_IDENTITY_PUBLIC_ORIGIN`, `GITMORA_IDENTITY_PREFIX` | Generated provider routing; `/auth` for the recommended same-domain profile. |
| `GITMORA_IDENTITY_CONFIG`, `GITMORA_IDENTITY_IMPORT` | Generated from bootstrap/active phase. Do not manually remount a retired bootstrap import. |

`KC_DB`, `KC_HEALTH_ENABLED`, `KC_METRICS_ENABLED`, `KC_HTTP_RELATIVE_PATH`, `KC_HTTP_MANAGEMENT_RELATIVE_PATH`, `KC_RUN_IN_CONTAINER` and `LANG` are baked into the optimized identity image. `JAVA_OPTS_KC_HEAP` is set by its Compose profile (`-Xms128m -Xmx512m`). Use the root-path identity build only for a separate-host root provider. These are image/profile settings, not new app env keys.

## Source-build settings

`make build build-image RELEASE_VERSION=0.4.4 RELEASE_REVISION="$(git rev-parse HEAD)"` stamps host binaries and the application image. Defaults are `development` and an empty revision. These are build inputs, not runtime env values. Tag the resulting local images immutably as described in [deployment](deployment.md); application and identity images are pinned independently.

## Developer CLI and agent settings

| Variable / flag | Behavior |
| --- | --- |
| `--server https://gitmora.example.com` | Exact own Gitmora origin for `auth`, `api`, `mcp`, and repository `init`. Credentials are isolated per server. |
| `WORKGRAPH_TOKEN` | Explicit automation override; takes precedence over saved OS login. Keep unset for normal desktop login. Never place a token into a repo, agent config, URL or argv. |
| `WORKGRAPH_<NAME>_TOKEN` | Optional collector token name selected by `init --token-env`; does not change API/MCP's explicit `WORKGRAPH_TOKEN` override. |
| `WORKGRAPH_KEYCHAIN_PATH` | Optional absolute private existing macOS keychain for controlled testing/administration; leave unset normally. Unsupported on Linux. |
| `CODEX_HOME` | Codex configuration root; otherwise `~/.codex`. |
| `XDG_CONFIG_HOME` | OpenCode configuration root; otherwise the user's default config directory. |
| `HOME`, `PATH`, `XDG_RUNTIME_DIR`, `DBUS_SESSION_BUS_ADDRESS` | Normal OS/session environment. On Linux, interactive auth requires installed `secret-tool` and an unlocked Secret Service/D-Bus session. |
| `GIT_CONFIG_GLOBAL`, `GIT_CONFIG_NOSYSTEM`, `GIT_ALLOW_PROTOCOL`, `GIT_TERMINAL_PROMPT`, `GIT_LITERAL_PATHSPECS`, `GIT_NO_LAZY_FETCH`, `GIT_NO_REPLACE_OBJECTS`, `GIT_OPTIONAL_LOCKS` | Existing Git environment; some are deliberately sanitized or fixed by bounded local Git subprocesses. They are not Gitmora server settings. |

Test-only `WORKGRAPH_TEST_*`, `GITMORA_*TEST*`, `TASKTOPIA_SOURCE`, `TASKTOPIA_NODE` and browser verification switches belong to [development](development.md), not production runtime. `HTTP_PROXY`/`HTTPS_PROXY` do not select provider destinations; configure the explicit provider proxy variables. There is no model-provider key, GPU setting or server inference configuration.
