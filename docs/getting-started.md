# Начало работы с Gitmora

Gitmora хранит разрешённые сессии ваших локальных агентов, связывает их с коммитами, MR и задачами и возвращает точные источники через веб, CLI и MCP. Модель запускает ваш Codex/OpenCode со своими настройками. Серверу Gitmora не нужны GPU и ключ модели.

## 1. Учётная запись и проект

Откройте [Gitmora](https://gitmora.tasktopia.online): нажмите «Войти» или «Создать аккаунт». Публичная регистрация на этом сервере включена. В другой установке с закрытой регистрацией оператор [создаёт пользователя командой](accounts.md#create-a-user-on-a-selected-docker-installation). Затем оператор добавляет пользователя в участники проекта: новый аккаунт не получает доступ к чужим проектам автоматически. Язык можно выбрать до входа; оформление меняется в личных «Настройках» внизу бокового меню.

Оператор создаёт проект Gitmora в «Проектах», регистрирует репозиторий в «Репозиториях» и настраивает GitLab или GitHub в «Настройках проекта». Адрес — базовый URL экземпляра GitLab, например `https://gitlab.company.ru` или `https://code.company.ru/gitlab`, а ID — числовой Project ID из GitLab. Не вводите полный URL `group/project` в поле адреса сервера. Для своего GitLab сначала выполните [настройку сети и CA](gitlab-self-managed.md).

Для GitHub выберите хостинг **GitHub** и введите полную ссылку на публичный репозиторий: ID определится автоматически. Затем сохраните публичный доступ или отдельный токен чтения. [Пошаговая настройка и ограничения](github.md).

## 2. CLI на компьютере разработчика

В приложении откройте **«Подключение»**, выберите свою ОС и скопируйте команду установки. Она скачивает конкретную версию, проверяет два именованных SHA-256 и устанавливает CLI в `$HOME/.local/bin`. Если CLI уже установлен с другими байтами, замена требует явного проверенного хеша. [Подробная установка и обновление](native-installation.md).

Нужны Git 2.43+, curl и поддерживаемая ОС: macOS или Linux. Для входа macOS использует Keychain; Linux — `secret-tool` и разблокированный Secret Service/D-Bus в пользовательской сессии. В Ubuntu пакет называется `libsecret-tools`. На headless-сервере без хранилища секретов интерактивный вход не заработает: для контролируемой автоматизации предусмотрен явно заданный `WORKGRAPH_TOKEN`, см. [правила ключей](cli-auth.md). Windows пока не поддерживается. Intel macOS поставляется как cross-build; отдельный тест на физическом Intel Mac ещё не выполнен.

Добавьте `$HOME/.local/bin` в PATH своего shell-профиля. Если агент запускается из GUI и не видит этот PATH, укажите абсолютный путь к `gitmora` в его конфигурации.

```sh
gitmora version
gitmora auth login --server https://gitmora.tasktopia.online
gitmora auth status --server https://gitmora.tasktopia.online
```

Сравните код в терминале и браузере и подтвердите свой запрос. Пароль не вводится в CLI, а ключ не нужно копировать в агент. Вход имеет срок действия; истёкший или отозванный вход требует повторного `auth login`.

## 3. Сбор сессий и обычный Git push

Клонируйте репозиторий обычным способом. В Gitmora откройте «Репозитории» → нужный репозиторий → «Подключить CLI и локальных агентов». Выполните показанную `gitmora init` внутри локального checkout с настроенным `origin`: команда уже содержит точные URL Gitmora и UUID репозитория.

Включите используемый агент:

```sh
gitmora agent enable codex
# В Codex откройте /hooks, проверьте и разрешите команды Gitmora.
# Либо:
gitmora agent enable opencode
gitmora status
```

После установки перезапустите агент. Работайте, делайте обычные `git commit` и `git push`. Сбор идёт только для явно подключённых репозиториев и разрешённого агента. Сессия без связи с коммитом остаётся локальной. GitLab отдельно подтверждает существование SHA, MR и CI; завершение `push` не означает, что сервер уже закончил сверку.

При отсутствии связи сохраняется локальная очередь. После восстановления:

```sh
gitmora sync --retry
gitmora status
gitmora disable
# Возобновить сбор:
gitmora enable
```

`disable` сохраняет уже накопленные данные и очередь. Только один агент в текущем репозитории отключается через `gitmora agent disable codex --local` или `opencode --local`. Уже отправленный запрос нельзя отозвать. [Жизненный цикл, foreign hooks и восстановление](collector.md), [особенности Codex](codex.md).

## 4. MCP и работа агента с контекстом

В «Подключении» раскройте «Поиск и контекст через MCP» и скопируйте конфигурацию для своего агента. Добавьте секцию в существующий файл, сохранив остальные настройки. Для Codex это `~/.codex/config.toml`:

```toml
[mcp_servers.gitmora]
command = "/absolute/path/to/gitmora"
args = ["mcp", "--server", "https://gitmora.tasktopia.online"]
```

После перезапуска попросите агент: «Через Gitmora покажи доступные проекты, найди сессии по этой задаче и открой точные источники». Для списка проектов можно использовать `gitmora api get /v1/projects --server https://gitmora.tasktopia.online`; затем передать `project_id` инструменту `context.browse`. MCP сам не получает права на все проекты.

Доступны шесть инструментов: `context.browse`, `context.search`, `context.pack`, `context.expand`, `context.task`, `context.file`. Они читают разрешённые источники. Изменения каталога, участников и интеграций выполняются отдельными явными `gitmora api` командами при наличии необходимых прав; обычный CLI-вход не выдаёт административные полномочия. [CLI API и MCP](native-context.md), [поля, пагинация и ограничения контекста](context.md).

## 5. Проверка подключения

| Симптом | Что проверить |
| --- | --- |
| `gitmora: command not found` | PATH или абсолютный путь в конфигурации GUI-агента. |
| CLI не сохраняет вход | Keychain/Secret Service, текущую пользовательскую сессию, `auth status`. |
| Нет проектов / HTTP 403 | Членство и права ключа. Вход сам по себе не назначает роль. |
| `init` не совпадает с репозиторием | Рабочую папку, `git remote -v`, точный UUID и базовый адрес экземпляра GitLab. Не добавляйте пароль в URL origin. |
| MCP не запускается | Абсолютный путь CLI, сохранённый вход в тот же сервер, отсутствие лишнего текста в stdout; `gitmora mcp --help`. |
| Сессия есть локально, но отсутствует в вебе | Разрешения агента/репозитория, связь с коммитом, `status`, `sync --retry`, серверную сверку/index. |
| MR/CI ещё не видны | Состояние GitLab в настройках, «Запросить сверку», ожидание фоновой обработки. |
| Свой GitLab недоступен | Exact allowlist, DNS/route, порт, доверенный CA; [таблица диагностики](gitlab-self-managed.md). |

Tasktopia подключается отдельно сервисным доступом к выбранной стране. Без него базовые сессии/коммиты/MR/поиск продолжают работать; карточки задач не подменяются выдуманными данными. [Настройка Tasktopia](tasktopia.md).
