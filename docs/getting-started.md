# Начало работы с Gitmora

Gitmora хранит разрешённые сессии ваших локальных агентов, связывает их с коммитами и MR/PR и возвращает точные источники через веб, CLI и MCP. Модель запускает ваш Codex/OpenCode со своими настройками. Серверу Gitmora не нужны GPU и ключ модели.

## 1. Учётная запись и проект

Откройте [Gitmora](https://gitmora.tasktopia.online), создайте аккаунт и первый проект. Вы станете администратором этого проекта. Другие проекты доступны только после добавления в их участники. Уже созданные проекты переключаются в верхней части левой панели; там же можно создать новый.

Первый экран предложит подключить репозиторий: выберите **GitHub** или **GitLab**, вставьте полную ссылку и выберите доступ. Можно ввести новый токен или использовать токен из уже подключённого репозитория этого проекта на том же сервере. ID определяется автоматически. Для публичного GitHub можно явно выбрать работу без токена, но общий лимит API подходит только для небольшого первого теста. Настройки подключения находятся в **Репозитории → Настроить**.

Повторное использование проверяет доступ к новому репозиторию и сохраняет отдельную зашифрованную копию API-токена. Права токена должны включать оба репозитория. Замена или отключение одного подключения не меняет остальные; вебхуки настраиваются отдельно. Отозванный у GitHub/GitLab токен перестанет работать во всех подключениях, где он используется.

Откройте **Участники** и добавьте коллегу по нику Gitmora или UUID, выбрав роль: чтение, участник или администратор. Коллега сначала регистрируется; свой ник и UUID он видит в личных настройках. Учётная запись может участвовать в нескольких проектах. При выключенной регистрации пользователя [создаёт оператор командой](accounts.md#create-a-user-on-a-selected-docker-installation).


Язык и тема меняются в **Личных настройках** внизу бокового меню. Технические настройки OIDC и общий список пользователей не входят в рабочий интерфейс проекта.

## 2. CLI на компьютере разработчика

В приложении откройте **CLI и MCP**. Установщик сам определит macOS/Linux и архитектуру, проверит контрольные суммы и установит CLI в `$HOME/.local/bin`:

```sh
curl -fsS --proto '=https' --tlsv1.2 https://gitmora.tasktopia.online/install.sh | sh -s -- --server https://gitmora.tasktopia.online
export PATH="$HOME/.local/bin:$PATH"
```

Для своей установки используйте её URL и передайте `--server` установщику: `curl -fsS https://gitmora.example.com/install.sh | sh -s -- --server https://gitmora.example.com`. Существующий CLI с другими байтами не заменяется автоматически. [Подробная установка и обновление](native-installation.md).

Нужны Git 2.43+, curl и поддерживаемая ОС: macOS или Linux. Для входа macOS использует Keychain; Linux — `secret-tool` и разблокированный Secret Service/D-Bus в пользовательской сессии. В Ubuntu пакет называется `libsecret-tools`. На headless-сервере без хранилища секретов интерактивный вход не заработает: для контролируемой автоматизации предусмотрен явно заданный `WORKGRAPH_TOKEN`, см. [правила ключей](cli-auth.md). Windows пока не поддерживается. Intel macOS поставляется как cross-build; отдельный тест на физическом Intel Mac ещё не выполнен.

Добавьте `$HOME/.local/bin` в PATH своего shell-профиля. Если агент запускается из GUI и не видит этот PATH, укажите абсолютный путь к `gitmora` в его конфигурации.

```sh
gitmora version
gitmora auth login --server https://gitmora.tasktopia.online
gitmora auth status --server https://gitmora.tasktopia.online
```

Сравните код в терминале и браузере и подтвердите свой запрос. Пароль не вводится в CLI, а ключ не нужно копировать в агент. Вход имеет срок действия; истёкший или отозванный вход требует повторного `auth login`.

## 3. Сбор сессий и обычный Git push

Клонируйте репозиторий обычным способом. В Gitmora откройте «Репозитории» → нужный репозиторий → «Подключить CLI и локальных агентов». Выполните показанную `gitmora init` внутри локального checkout с настроенным `origin`: команда уже содержит точные URL Gitmora и UUID репозитория.

Включите используемый агент:

```sh
gitmora agent enable codex
# В Codex откройте /hooks, проверьте и разрешите команды Gitmora.
# Либо:
gitmora agent enable opencode
gitmora status
```

После установки перезапустите агент. Работайте, делайте обычные `git commit` и `git push`. Сбор идёт только для явно подключённых репозиториев и разрешённого агента. Сессия без связи с коммитом остаётся локальной. GitLab отдельно подтверждает существование SHA, MR и CI; завершение `push` не означает, что сервер уже закончил сверку.

При отсутствии связи сохраняется локальная очередь. После восстановления:

```sh
gitmora sync --retry
gitmora status
gitmora disable
# Возобновить сбор:
gitmora enable
```

`disable` сохраняет уже накопленные данные и очередь. Только один агент в текущем репозитории отключается через `gitmora agent disable codex --local` или `opencode --local`. Уже отправленный запрос нельзя отозвать. [Жизненный цикл, foreign hooks и восстановление](collector.md), [особенности Codex](codex.md).

## 4. MCP и работа агента с контекстом

В «CLI и MCP» раскройте «Поиск через MCP» и скопируйте конфигурацию для своего агента. Добавьте секцию в существующий файл, сохранив остальные настройки. Для Codex это `~/.codex/config.toml`:

```toml
[mcp_servers.gitmora]
command = "/absolute/path/to/gitmora"
args = ["mcp", "--server", "https://gitmora.tasktopia.online"]
```

После перезапуска попросите агент: «Через Gitmora покажи доступные проекты, найди сессии по ссылке на этот MR/PR и открой точные источники». Для списка проектов можно использовать `gitmora api get /v1/projects --server https://gitmora.tasktopia.online`; затем передать `project_id` инструменту `context.browse`. MCP сам не получает права на все проекты.

Доступны шесть инструментов: `context.browse`, `context.search`, `context.pack`, `context.expand`, `context.resolve`, `context.file`. Они читают разрешённые источники. Изменения каталога, участников и интеграций выполняются отдельными явными `gitmora api` командами при наличии необходимых прав; обычный CLI-вход не выдаёт административные полномочия. [CLI API и MCP](native-context.md), [поля, пагинация и ограничения контекста](context.md).

## 5. Проверка подключения

| Симптом | Что проверить |
| --- | --- |
| `gitmora: command not found` | PATH или абсолютный путь в конфигурации GUI-агента. |
| CLI не сохраняет вход | Keychain/Secret Service, текущую пользовательскую сессию, `auth status`. |
| Нет проектов / HTTP 403 | Членство и права ключа. Вход сам по себе не назначает роль. |
| `init` не совпадает с репозиторием | Рабочую папку, `git remote -v`, точный UUID и базовый адрес экземпляра GitLab. Не добавляйте пароль в URL origin. |
| MCP не запускается | Абсолютный путь CLI, сохранённый вход в тот же сервер, отсутствие лишнего текста в stdout; `gitmora mcp --help`. |
| Сессия есть локально, но отсутствует в вебе | Разрешения агента/репозитория, связь с коммитом, `status`, `sync --retry`, серверную сверку/index. |
| MR/CI ещё не видны | Состояние GitLab в настройках, «Запросить сверку», ожидание фоновой обработки. |
| Свой GitLab недоступен | Exact allowlist, DNS/route, порт, доверенный CA; [таблица диагностики](gitlab-self-managed.md). |
