# Локальный Codex

Gitmora получает видимую историю через локальный Codex app-server API и связывает её с обычным Git. Модель и её настройки остаются в Codex. Сервер Gitmora не запускает модель или агента.

## Подключение

Установите актуальный CLI, выполните `gitmora auth login --server https://gitmora.tasktopia.online` и `gitmora init --server https://gitmora.tasktopia.online --repository-id <UUID>` в своём репозитории. Затем:

```sh
gitmora agent enable codex
```

Если Codex отсутствует в PATH, добавьте `--codex /полный/путь/к/codex`. `--config-dir /абсолютная/папка` выбирает другую папку конфигурации; по умолчанию используется штатный CODEX_HOME или `~/.codex`.

Откройте `/hooks` в Codex, проверьте четыре команды Gitmora и разрешите их запуск. После установки возобновите или перезапустите сессию. Установка сообщает `trust_required: true`; она не меняет хранилище доверия и не выдаёт себя за готовый сбор до нативного разрешения. Это штатное требование [Codex hooks](https://learn.chatgpt.com/docs/hooks).

Установщик сохраняет чужие hooks/config.toml, добавляет только свои группы SessionStart, PreToolUse, PostToolUse и Stop. Собственная запись установки и блокировка позволяют повторить прерванную установку. Изменённые команды считаются конфликтом и сохраняются. `gitmora agent disable codex` снимает только точные собственные группы.

## Сбор и доставка

- PreToolUse сохраняет текущий HEAD, исходную сессию и первоначальную задачу в локальном журнале. PostToolUse фиксирует первый наблюдённый конец. Отсутствующий конец не подменяется более поздним HEAD. Инструмент без изменения HEAD закрывается с явной причиной.
- Stop и SessionStart читают историю, нормализуют видимые сообщения и завершённые результаты инструментов, сохраняют ограниченные окна в SQLite. Сопоставление инструмента использует его точный native ID; привязка к коммитам применяется только к сохранённому интервалу.
- Обычные Git-хуки и сохранённое согласие push разрешают отправку относящегося контекста. Сессия без опубликованной связи остаётся локально; исключение — явный `sync --include-uncommitted`. Финальный ответ после сделанного агентом push также может дополнить уже разрешённую сессию.
- Фиксированные диагностические сообщения не останавливают инструменты Codex. Неудачная отправка остаётся в очереди; ошибка источника оставляет его в Codex. Gitmora не запускает дополнительные запросы к модели.

Если агент меняет файлы только командами оболочки и сам не делает коммит, такие изменения не дают native `fileChange`-свидетельств о путях. Поэтому более поздний ручной коммит не связывается с этой сессией автоматически. Явный `gitmora sync --include-uncommitted` разрешает опубликовать сессию без утверждения об авторстве коммита. Если агент делает коммит в собственном завершённом инструменте, Gitmora наблюдает интервал HEAD через PreToolUse/PostToolUse и связывает коммит с сессией. Подтверждённые native `fileChange` по-прежнему дают свидетельства о путях для существующего сценария с последующим ручным коммитом.

Чтение использует `initialize`, `thread/read` и страницы `thread/items/list` [официального app-server API](https://learn.chatgpt.com/docs/app-server). Обычный CLI поддерживается отдельным локальным процессом metadata API через stdio. Явный `--socket` в команде восстановления выбирает **control socket управляемого daemon**; публичный Unix/WebSocket listener имеет другой протокол. Адаптер не вызывает thread/resume, turn/start или подтверждения инструментов и не читает нестабильные rollout/transcript-файлы сам.

## Отключение и восстановление

```sh
gitmora status
gitmora agent disable codex --local
gitmora agent enable codex --local
gitmora disable
gitmora enable
```

Локальные политики действуют на общий репозиторий, включая связанные worktrees. Запись и доставка отключённого агента прекращаются; очередь сохраняется. Глобальное удаление хуков и локальное отключение — разные действия. Подробности повреждённой/восстановленной базы и очередей: [collector](collector.md#hook-ownership-and-disable).

`status` показывает `pending_tools` и `tools_missing_end`. Если сессия была прервана или источник временно недоступен, восстановление выполняется при следующем SessionStart/Stop либо явно:

```sh
gitmora frontier list
gitmora agent capture codex --session <native-thread-ID>
gitmora sync --retry
```

Если результат инструмента не успел наблюдаться (например, асинхронная команда пережила завершение сессии), автоматическая атрибуция не угадывает конец. Проверенный оператором SHA можно задать через `frontier resolve --id <hash> --end <full-SHA> --reason <text>`, затем повторить capture и sync. Ненужную связь закрывает явный `frontier abandon --id <hash> --reason <text>`. `frontier list` содержит исходную сессию; чужой worktree не может применить её запись.

## Покрытие и границы

Проверенная установленная версия — Codex CLI `0.164.0-alpha.11.1`. История должна принадлежать тому же физическому Git worktree, включая запуск из его подпапки. Идентичность и метаданные потока проверяются до и после чтения страниц. Смена истории, циклический cursor, неизвестный запрос на выполнение/подтверждение или превышение границ отклоняются без выдуманного результата.

Сохраняются текст пользователя/ассистента/плана и текстовое представление завершённых команд, fileChange, MCP/dynamic/function результатов. Фрагменты пользователя остаются отдельными; секреты редактируются до разбиения длинного текста. Подтверждённые native fileChange дают пути внутри текущего репозитория. Команда оболочки сама по себе не доказывает построчное авторство или каждый изменённый файл. Hidden reasoning, бинарные вложения и неизвестные типы не превращаются в разговор; ручной capture сообщает `skipped_types`. Hooks дочерних агентов могут нести родительский session_id: отдельная история ребёнка автоматически не заявляется как захваченная.

Одно чтение ограничено 12 секундами, 10 000 items и 64 MiB протокола; отдельный item — 16 MiB, строка протокола — 20 MiB. Текст делится на UTF-8-фрагменты до 64 KiB и окна примерно до 1 MiB/512 сообщений. Неполный источник не выдаётся за полный. Неизвестные версии Codex требуют отдельной проверки; пользовательский model slug при ручном восстановлении можно указать через `--model`, иначе он честно неизвестен.

`make smoke-codex` использует установленный Codex, отдельный временный профиль, проверенные тестовые hooks и детерминированный Responses endpoint на localhost. Проверяются реальный инструмент, commit/push, поздний ответ, редакция секрета и API/PostgreSQL. Платная модель и личная история пользователя не используются. Автоматическое доверие допускается только для четырёх явно проверенных временных команд **в этом тесте**; продукт по-прежнему требует `/hooks`.
