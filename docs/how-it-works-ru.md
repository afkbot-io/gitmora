# Как работает Gitmora

Разработчик работает в привычном агенте: Codex, OpenCode или другом подключённом инструменте. Gitmora CLI сохраняет разрешённую историю работы локально и связывает её с задачей и коммитами. Для обычных `git commit` и `git push` используются совместимые Git-хуки. При недоступном сервере данные остаются в офлайн-очереди и отправляются позднее.

GitLab хранит код, MR и CI. Gitmora подключается к API выбранного проекта; webhook ускоряет обнаружение изменений. Сервер независимо сверяет SHА и связи, поэтому запись агента о коммите не считается подтверждением GitLab. Tasktopia остаётся местом постановки и приёмки задач; Gitmora добавляет связь задачи с историей реализации.

Веб-интерфейс показывает проекты, сессии, задачи, MR, поиск и точные источники. Агент через CLI/MCP получает те же разрешённые источники и использует собственную модель. Сервер Gitmora хранит, синхронизирует и индексирует данные. Встроенных моделей, Q&A и автономного ревью в текущем продукте нет.

Вход в веб и CLI относится к одной учётной записи. Регистрация управляется `WORKGRAPH_REGISTRATION_ENABLED`; доступ без авторизации не появляется. Когда регистрация закрыта, пользователя создаёт оператор командой `gitmorad users create`. Новому пользователю отдельно назначают роль в проекте. Сбор по агенту/репозиторию и интеграции можно отключить.
