# Как работает Gitmora

Gitmora хранит историю работы локальных ИИ-агентов и связывает её с коммитами и MR/PR. Платформа разворачивается на вашем сервере; модель выбирает и запускает сам разработчик в Codex или OpenCode.

1. Создайте проект, добавьте участников и подключите GitHub или GitLab по ссылке на репозиторий и токену чтения. Для собственного GitLab или GitHub Enterprise оператор настраивает разрешённый адрес сервера.
2. Установите CLI, войдите через браузер и выполните команду подключения из раздела «CLI и MCP» внутри клонированного репозитория.
3. Включите сбор для своего агента. Работайте, делайте коммиты и `git push`. Разрешённые записи попадают в локальную очередь и доставляются на сервер; при отсутствии сети очередь сохраняется.
4. Сервер независимо сверяет коммиты, MR/PR и CI через GitHub/GitLab и индексирует доступную историю. Заявление агента о коммите не заменяет подтверждение провайдера.
5. Найдите сессию по тексту, полному SHA или ссылке на MR/PR. Либо подключите MCP к агенту и попросите получить контекст нужного MR/PR.

Задачи остаются во внешнем задачнике. Достаточно прикрепить к задаче MR/PR: его ссылка позволяет найти коммиты и сохранённые сессии в Gitmora. Отдельного доступа к задачнику не требуется.
