# Требования базовой Gitmora

Базовый продукт хранит и находит контекст разработки. C01–C18 описывают его функциональные и проверочные требования. Архитектура и границы — в [описании системы](system-analysis.md), воспроизводимые команды — в [руководстве разработки](development.md).

| ID | Требование | Прямое доказательство |
| --- | --- | --- |
| C01 | Self-hosted платформа без серверных моделей, генерации ответов и автономных агентов | Удалённые активные модули/маршруты/роли/настройки, проверенная сборка и фактическое развёртывание |
| C02 | Каталог проектов/репозиториев с неизменными GitLab ID и привязкой задач | Доменные/SQL/API/CLI проверки CRUD, конфликтов и сохранности данных |
| C03 | Единая учётная запись, регистрация, вход и выход | Реальные браузерные проверки, безопасные сессии, CSRF, неверные данные, выход и отзыв доступа |
| C04 | Регистрация отключается через env; авторизация обязательна; есть команда создания пользователей | Запросы при включённой/выключенной регистрации, CLI со скрытым паролем и вход созданным пользователем |
| C05 | Права участников и отзывные ограниченные ключи без неявного повышения доступа | Разделение проектов/пользователей, отрицательные API/MCP сценарии, отзыв/срок действия и CLI-вход |
| C06 | Сессии нескольких локальных агентов, прежде всего Codex/OpenCode | Адаптеры и сценарии событий/транскриптов, точные идентификаторы, отсутствие выдуманной атрибуции |
| C07 | Включение/отключение сбора и интеграций с понятным статусом | CLI/UI сценарии отключения, сохранение чужих настроек и отсутствие последующего сбора |
| C08 | Надёжный локальный сборщик, офлайн-очередь и восстановление после сбоев | Реальный Git/SQLite, повторная доставка, потеря ACK, перезапуск и восстановление очереди |
| C09 | Обычные commit/push, все относящиеся коммиты, worktrees и переписывание истории | Bare-remote, чужие хуки, multi-commit push, amend/rebase, неуспешный push |
| C10 | GitLab API/webhooks и проверенные связи коммит/MR/CI | Авторизация доставки, дубликаты/порядок, reconciliation, смена head, squash и реальные разрешённые чтения |
| C11 | Tasktopia: задачи, документы, MR и ссылки на сессии | Реальный MCP-контракт, правильные UUID, повтор/перезапуск и сохранение процесса задач |
| C12 | Поиск сессий/задач/документов/доступного кода с правами до выдачи | PostgreSQL-поиск, качество выдачи, точные ссылки/версии, отсутствие чужих фрагментов и честное покрытие |
| C13 | Работа с базовыми данными через CLI и MCP из внешних агентов | JSON-контракты, контекст/поиск/источники/разрешённые действия, реальный клиентский сценарий |
| C14 | Единый интерфейс Tailwind, включая вход и регистрацию | Общие компоненты, типизация, браузер/мобильные/клавиатурные проверки, ошибки и пустые состояния |
| C15 | Совместимость с Entire/Git AI для базового сбора | Импорты, происхождение/версии/границы поддержки без ложного авторства |
| C16 | Секреты, ограничения, права, корректное удаление и отсутствие утечек | Редакция/лимиты/ошибки, защита интеграционных ключей и сохранность данных |
| C17 | Проверенная сборка, миграции, фоновые синхронизация/индексация и доставка | Старая/новая БД, живые роли, сбои/перезапуск и сохранность Gitmora/Tasktopia |
| C18 | Чистые границы, типизация, код-стайл, TDD, документация и глубокое ревью | Модульные ревью, соответствующие тесты и финальный аудит каждого C-пункта |

Серверный ИИ, вопросы/ответы, автономное ревью и расширенная редакционная база знаний исключены. Семантический поиск с отдельной серверной моделью не требуется: внешний агент использует собственный ИИ и инструменты Gitmora. Команда 10–50 человек — целевой сценарий, требующий проверки, а не обещание производительности.
